# CI timing measurements: 2026-09-15

## Result

With dependency cache hits, the validation gate completed in 255 (245–289) seconds (median and range), compared with 240 seconds in the initial cache-miss sample. Rust test steps were shorter at the warm median on all four native targets. The Intel Mac Lua/Deno suite remained the largest native test stage; cache hits did not consistently reduce end-to-end elapsed time.

## Method

The measured implementation is [`c55812a`](https://github.com/wadackel/diffreel.nvim/commit/c55812afa980c14ccc8c27e5dc0d18887ab3b470). Attempts 1–4 of the same push workflow use the same commit, ref, configuration, and test coverage. Attempt 1 missed the Nix store and native Rust/Deno dependency caches; attempts 2–4 restored them successfully. Consumer Deno caches were already hits in attempt 1.

Every attempt reused the existing release and passed all static, native, and consumer jobs. Each of the four native targets ran 24 Rust tests and all 66 Lua/Deno suite commands with `--jobs 2`, including the exclusive unit, stability, and stateful groups. No caches were manually cleared, and no source or workflow setting was changed between samples.

Runtime versions were Rust 1.97.1, Deno 2.9.5, Neovim 0.12.5, and Git 2.55.0. macOS used Apple Silicon `macos-14` and Intel `macos-15-intel`; Linux used arm64 `ubuntu-24.04-arm` and x86_64 `ubuntu-24.04`.

All four executable identities come from the immutable [release manifest](https://github.com/wadackel/diffreel.nvim/releases/download/daemon-dd0761796600e0735680bc212073d470115f938d96f0e05ee96f6c70b29b73e2/manifest.json), build ID `dd0761796600e0735680bc212073d470115f938d96f0e05ee96f6c70b29b73e2`. The recorded suite environments confirm the same build ID and target in each sample.

Times below are seconds. **Validation** ends when identity, both static-check jobs, and all four native jobs have completed. **All jobs** also includes publication verification and four consumer jobs. Both start at the attempt's `run_started_at`, so they include scheduling gaps. **Job sum** adds job start-to-completion durations; it is not elapsed workflow time or a billing estimate. The last job's completion timestamp is used instead of the run's later metadata update.

## Interpretation and limits

- The Rust test step was shorter at the warm median on every native target. The Intel Mac Lua/Deno suite remains the main contributor to the validation wait; its execution time varies even with dependency cache hits.
- This is one initial cache-miss sample and three cache-hit samples on shared GitHub-hosted runners. It does not isolate cache effects from host load or scheduling variability, and it does not establish an SLA.
- Repeating the same commit can reuse caches differently from testing a new commit or runner image. These samples do not predict every subsequent PR or release build.
- These runs reuse an existing daemon release. They do not measure a new Rust release build, and they do not isolate the effect of `--jobs 2` against serial execution.
- The [earlier workflow](https://github.com/wadackel/diffreel.nvim/actions/runs/34913999117/attempts/1) took 467 seconds through its last job, but it used commit `6072f3e`, built new release binaries, and had a different workflow. Its difference from these samples is not a controlled speedup measurement.

## Reproduction

Use `gh run view 34920240140 --attempt <n> --json jobs` for step timestamps and the attempt-specific Actions links above for logs. The REST attempt endpoint supplies `run_started_at`. Each native `evidence-<target>` artifact contains `environment.json` and `results.json`; restore-step logs identify cache hits/misses and cache keys. Preserve these before rerunning because artifact/log retention is finite.

Repeat comparisons with the same source, toolchain, executable build ID, test coverage, and release-reuse state. Record failed samples and scheduling gaps as well as successful durations. Keep new raw logs and captures under `.wadackel/qa/`, following the [maintenance guide](../maintenance.md#release-workflow).
